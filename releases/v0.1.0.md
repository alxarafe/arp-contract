tag and corresponding GitHub Release. This document alone does not publish it.

- **Prospective annotated tag:** `v0.1.0`.

- **Release date / SHA:** Verify using the final tag and GitHub Release metadata;
  do not record an unverified or self-referential commit SHA here.

## Normative feature and scope

- **ARP-DICT-001:** Reusable scalar data dictionary MVP, including 17 scalar
  types, registration of source snapshots, immutable catalog construction,
  deterministic resolution, scalar validation and normalization.
- **Specification:** `docs/features/arp-dict-001.md`.
- **Document format:** `arp.dictionary/v1` (portable JSON and bounded YAML).
- **Schema:** `schemas/dictionary/v1/dictionary.schema.json` (JSON Schema Draft
  2020-12) plus semantic/parser rules defined by the feature specification.
- **Common intake limits:** 1 MiB UTF-8, 2048 elements per source, collection
  depth 128, numeric token length 256, absolute exponent 128 and absolute
  numeric magnitude strictly below `10^128`.
- **Scalar numeric input:** retains its independent 4096-digit safety limit.

## Classification and migration

- First functional release: **MINOR** (`0.1.0`). No previous published ARP
  contract exists, therefore no prior ARP release is broken.
- The YAML and source numeric portability profile was finalized **before** first
  publication. These changes refine the unpublished candidate, not a PATCH of an
  already published contract.
- **Migration from earlier ARP releases:** None.
- **Migration from existing Erbas contracts:** No automatic mapping or conversion;
  consumer-owned bindings must explicitly reconcile their value and resource
  semantics. No claim of direct Erbas wire compatibility is made.

## Feature exclusions

No persistence, SQL/ORM, HTTP service, resource CRUD, field contextuality,
workflow/BPMN, business rules or UI runtime are included in this release.
These remain independent prospective capabilities under the ARP architecture.

## Publication and adoption boundary

The release must follow `docs/release-process.md`: reviewed release change,
annotated release-candidate tag, version-pinned revalidation, final immutable
annotated tag and GitHub Release. Its published SHA must be recorded externally
without rewriting this historical inventory. Runtime adoption is a separate
version-pinned activity; mark `PASS` only with the published tag/SHA and actual
per-runtime test evidence, never merely on the basis of this inventory.
